A reliability release: a review of what happens when people edit the same things at the same time, with every fix covered by new tests (including a second two-editor test suite for the tricky cases).

**[Download GodotCoop-windows.zip](https://github.com/i-Roboticist/godot-coop/releases/download/v1.1.0/GodotCoop-windows.zip)**, unzip it and run `GodotCoop.exe`. Everyone in a session needs this version (1.0 and 1.1 refuse to connect to each other, with a message saying so).

### Scripts
- Closing and reopening a script no longer makes your later edits disappear.
- Saving while you're still typing no longer duplicates or drops the last few characters for teammates.
- Edit > Undo and the right-click Undo can't revert a teammate's typing any more; Ctrl+Z still undoes only your own.
- Multi-caret edits and Replace All no longer shift a teammate's typing that happens between the carets.
- A brand-new script keeps what you typed even if the file hasn't reached the host yet.
- Edits made during a reconnect are kept, and teammates' carets disappear when they close the file.

### Scenes
- Change Type works (it used to error and revert).
- Two people adding a node with the same name at once now end up with the same names in both editors.
- A node or script whose file hasn't arrived yet appears once the file does.
- A teammate saving a scene you've instanced refreshes it without losing your unsaved edits.
- Teammates' changes mark the scene as unsaved, so closing it asks to save.
- A property that a `@tool` script or animation preview changes every frame no longer floods everyone.
- Make Unique stays unique, and deleted animation tracks are removed for everyone.

### Files and sessions
- A change still uploading when the connection drops (or when you quit) is sent after you reconnect instead of being overwritten.
- Two people saving the same file at once end up with the same version, and the other is kept in `.coop/conflicts/`.
- Case-only renames (`Player.gd` to `player.gd`) and files that can't be written no longer delete the file for everyone.
- Project settings changed at the same moment end up the same everywhere, and changes made while you were disconnected arrive when you reconnect.
- Rejoining big projects is faster (unchanged files aren't hashed again).

### Security
- Built-in `@tool` scripts inside a teammate's scene change only run if you trust them, like `@tool` script files.
- C# code and MSBuild files are held for review like other code; `@tool` can't be hidden behind a long comment.
- Folder names like `.Coop/` or `.GIT/` and nested `.git` folders can't be used to slip files past the ignore rules on Windows; more reserved Windows file names are refused.
- When hosting, files from joiners are never trusted automatically.
